Информационная безопасность

Безопасность бессерверных приложений

Распространённый миф гласит, что Serverless автоматически безопасен. На деле вектор атак смещается с сетевого уровня на уровень прав IAM, конфигураций шлюзов и зависимостей кода.

1. Модель разделенной ответственности (Shared Responsibility Model)

В облачной архитектуре безопасность — это двусторонний контракт между провайдером и клиентом:

Ответственность провайдера (Cloud Security)

  • Физическая безопасность дата-центров.
  • Изоляция гипервизора и ядра ОС (Firecracker/gVisor).
  • Патчинг уязвимостей операционной системы и рантайма.
  • Защита сетевых магистралей от канального DDoS (L3/L4).

Ответственность разработчика (App Security)

  • Конфигурация политик доступа IAM.
  • Валидация входящих данных и санитайзинг.
  • Безопасное хранение API-ключей и паролей к базам.
  • Аудит уязвимостей сторонних npm/pip пакетов.

2. Управление доступом и правами (IAM)

Главное правило бессерверной безопасности: Принцип наименьших привилегий (Principle of Least Privilege).

Типичная грубая ошибка новичков — привязать к функции административную роль (AdministratorAccess или *:*). Если злоумышленник внедрит инъекцию в функцию, он получит полный контроль над всем облачным аккаунтом компании.

Золотое правило настройки ролей:

Каждая функция должна иметь собственную выделенную роль IAM. Если функция генерации превью изображений только читает из бакета raw-uploads и пишет в processed-thumbs, у неё не должно быть прав на удаление файлов или чтение базы данных пользователей.

3. Защита периметра API Gateway

Шлюз API является первой линией обороны. На уровне шлюза реализуются следующие механизмы:

  • Web Application Firewall (WAF): Фильтрация ботнетов, SQL-инъекций и вредоносных IP-адресов до того, как они достигнут кода.
  • Rate Limiting & Throttling: Ограничение числа запросов (например, не более 50 req/sec с одного IP) для предотвращения DoS-атак.
  • Валидация схемы JSON Schema: Шлюз отбрасывает запросы с некорректным телом до запуска функции, экономя время CPU и средства.
  • JWT Authorizers: Проверка подписи токена авторизации силами шлюза без выполнения кастомного кода.

4. Хранение секретов и переменных окружения

Ни в коем случае не коммитьте пароли от баз данных, приватные ключи и API-токены в Git-репозиторий!

В Serverless для безопасного хранения используются специализированные хранилища секретов:

  • AWS Secrets Manager / AWS Systems Manager Parameter Store: Шифрование ключами KMS, автоматическая ротация паролей и версионирование.
  • Yandex Lockbox: Надежное централизованное хранилище конфиденциальных данных в Yandex Cloud.
  • Переменные окружения среды (Environment Variables): Передаются в зашифрованном виде при развёртывании и считываются процессом во время холодного старта.

5. Защита от «Denial of Wallet» (Отказ кошелька)

Так как FaaS эластично масштабируется до тысяч экземпляров, атака перегрузки (Flood) может привести не к падению сервера, а к гигантскому денежному счёту.

Меры противодействия:

  1. Установка лимитов одновременных выполнений (Concurrency Limits): Ограничьте предел функции (например, не более 200 одновременных вызовов).
  2. Бюджетные алерты (CloudWatch Alarms / Cost Alerts): Настройка автоматического SMS/Email оповещения при превышении дневного бюджета (например, $10/день).
  3. Использование Captcha (Cloudflare Turnstile): Защита открытых публичных форм от спам-ботов.

6. Распределенный трейсинг и аудит

В монолите все логи пишутся в один файл на диске. В бессерверной системе 10 000 функций пишут логи в реальном времени из изолированных контейнеров.

Для расследования инцидентов применяются системы распределённого трейсинга:

  • AWS X-Ray / OpenTelemetry: Каждому входящему HTTP-запросу присваивается сквозной trace-id, который передаётся по цепочке через шлюз, функцию, очередь и базу данных. Это позволяет точно видеть, на каком шаге возникла задержка или ошибка.
  • Структурированное логирование (JSON Logging): Вывод логов в формате JSON (уровень INFO/ERROR, userId, executionDuration) для мгновенного поиска в CloudWatch Logs Insights.

Чек-лист разработчика по безопасности Serverless

  • ✅ Гранулярные IAM-роли: Каждая функция имеет доступ только к своим ресурсам.
  • ✅ Секреты вынесены: В репозитории нет паролей, ключей API и секретов.
  • ✅ WAF и Rate Limiting: Шлюз защищён от флуда и автоматических сканеров.
  • ✅ Валидация входа: Тело каждого запроса строго валидируется по схеме.
  • ✅ Лимиты Concurrency: Настроен потолок параллельных выполнений и бюджетные алерты.
  • ✅ Аудит зависимостей: Регулярный запуск npm audit или Snyk для выявления уязвимостей в библиотеках.
